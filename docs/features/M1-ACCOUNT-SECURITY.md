# M1 — Account Security Foundation

**Status:** Implemented locally  
**Milestone:** M1  
**Last updated:** 2026-07-23

## Scope

Password reset uses Django's signed, expiring token flow and always returns the
same request response. Local development uses the configured console backend;
tests use the in-memory backend. Production continues to require configured SMTP
credentials and a sender identity. Reset links are generated by Django and no
external redirect is accepted.

`User.account_status` is additive and defaults existing accounts to `active`.
Suspended and closed accounts are made inactive, invalidating authenticated
sessions and blocking login, seller workflows, favorites, checkout, and staff
routes. Status changes use the audited account service; superusers can restore
accounts through Django admin actions.

`AccountSecurityEvent` is append-only in application use. It records actor,
subject when known, event type, timestamp, a keyed IP hash, bounded user agent,
and bounded request identifier. It never stores passwords, reset tokens, session
cookies, authorization headers, or raw IP addresses.

`provision_staff_groups` idempotently reconciles `moderator`, `support`,
`finance`, and `operations` groups without assigning users. Administrators must
separately grant `is_staff` and an appropriate group. Management console links
remain permission-driven.

## Deferred decisions

DEC-003 and DEC-101 remain unresolved. This work deliberately adds neither phone
verification/provider traffic nor email verification. Sensitive email-change
policy remains deferred until DEC-101 is accepted.

## Operations and rollback

Run `make provision-staff-groups` after migrations to reconcile role
permissions. Apply the additive accounts migration before application rollout;
rollback is a forward fix because audit history is retained.
